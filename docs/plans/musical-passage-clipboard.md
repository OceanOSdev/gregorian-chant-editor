# Musical passage clipboard — implementation handoff

Status: owner-approved design, 2026-11-15. Base: master after PR #87 (contiguous selection). Implement on `feat/musical-passage-clipboard`; open a PR against master, do not merge.

## Goal and scope

Make recurring passages reusable when authoring longer chants (Kyrie XI, next repertoire target Dominican Salve Regina). Copy a complete neume or contiguous range, then paste music as one atomic insertion. The owner approved all eight policies below. No new selection kind, document schema/version, persisted clipboard, engraving change, dependency, system clipboard integration, cut, range deletion/movement, transposition, or lyrics copy. No new ADR required unless implementation discovers a genuine conflict with existing accepted ADRs; surface such conflicts instead of silently changing them.

## Owner decisions

1. Copy divisions strictly inside the selected neume interval, not leading/trailing divisions.
2. Preserve relative diatonic degree and effective alteration under the destination clef; omit source clef changes (including internal ones).
3. Preserve copied authored signs and effective pitches of copied AND pre-existing destination notes; reject incompatible paste, never synthesize compensating accidentals or silently change melody.
4. Copy signs by owner; remap internal explicit above-note placement anchors; if the source placement anchor is outside the copied interval, restore default before-owner-neume placement.
5. Paste immediately after the selected note's complete neume, selected whole neume, or last neume in canonical range order; with no selection append at true score end.
6. Internal application clipboard survives document replacements within the running session; no system clipboard access or persistence.
7. Music-only. Keep destination syllable anchors/text/alignment unchanged; derive membership using ordinary preceding-anchor semantics.
8. Select the inserted passage, with fresh IDs; focus the first constituent of its final neume.

## Copy contract

- Eligible selection: whole neume or valid contiguous neume range (direction independent, canonical document order); no selection or a note-only selection does not copy partial neumes. User can Shift-select the whole neume. Syllable/division/clef/clef-change/accidental selections are not valid copy targets. Stale IDs fail without replacing clipboard. Equal endpoints normalize as existing selection does.
- Capture a detached immutable snapshot of complete neumes, constituent order, kind, note form, mora, horizontal/vertical episema, and each constituent's effective relative degree and alteration (-1/0) from the full source document via resolveEffectivePitches/pitchContexts. Preserve source-local relationships by keys or indexes; source IDs are only local mapping keys, never reusable pasted IDs. No source document dependency after copy. No text, syllable anchors, source clefs, pixels, layout, derived custodes, staff/system breaks, or invented word-reset metadata.
- Capture divisions in deriveScoreOrder strictly after first and before last selected neume, preserving exact mixed order among included neumes/divisions (omit clefs). One-neume copy contains no divisions; multiple divisions at same internal slot keep order. Exclude all events before first or after last neume, even if visually adjacent.
- Copy each written sign whose owner is a selected note (including redundant natural/flat). If above-note anchor is selected, preserve local relation; otherwise omit placement (default). Do not copy a sign owned outside the range even if its engraving anchor lies inside it. Source effective pitches still include all inherited effects, whether their signs are copied or not. Capture does not reject merely because inherited context may later fail at a particular destination. Unsafe pitch arithmetic/invalid source returns a reason, leaves previous clipboard intact.
- Copy changes only clipboard/announcement, never selection, focus, document identity, history, redo or persisted bytes. Re-copy replaces snapshot. Clipboard remains across New, Import, bundled examples, cache reload/replacement, undo/redo and edits. Browser refresh/new tab starts empty. Clipboard is never exported or read from operating system.

## Destination and paste command

- Resolve semantic selection, not DOM focus. For selected note/neume/range resolve the last selected musical neume (canonical order, not directional endpoint), find it in deriveScoreOrder and use scoreBoundaryAt(order, index+1), then resolveScoreBoundary against latest document. This inserts BEFORE any existing division/clef run following that neume, consistent with contextual I after a neume. E.g. A | C-clef B -> select A, paste P -> A P | C-clef B. With none use scoreBoundaryAt(order, order.length), AFTER all trailing events (including finalis or trailing clefs); never silently move trailing punctuation. Empty music works. Syllable/clef/clef-change/division/accidental targets explicitly reject (do not fall back to append or infer from focus). Stale musical targets reject. No replacing existing music, no graphical paste tool; I remains unchanged and rejects ranges.
- Derive effective destination clef from initial clef plus last authored clef strictly preceding the exact score boundary (not from next neume or source clef). All inserted notes use this clef, since source internal clefs are omitted. For each source degree d use staffPosition(d - clefOffset(destinationClef)); safe-integer and existing document/geometry validity rules. Preserve all contours/appearance. Never transpose, clamp, normalize away a modifier, introduce a clef, or change existing staff positions. Reject unsafe/unrepresentable values with reason.
- Construct a single candidate mixed score order by splicing mapped neumes and copied internal divisions at resolved scoreIndex; reanchorScoreOrder reconstructs divisions/clef changes, preserve existing entity identities and relative order. Build neume array in matching canonical order. Do not loop ordinary single insert operations with intermediate accidental reconciliation/history; those can reject transiently or alter existing signs. Allocate fresh globally unique IDs for every pasted neume, constituent, division and accidental. Remap copied owners and retained placement anchors to pasted note IDs, never to old source or existing destination IDs. Existing lyrics (including alignment) remain exact; music-only insert inherits normal destination syllable membership, before first anchor remains untexted. Omitted source word resets may make paste incompatible; no synthetic lyric anchors.
- Validate whole candidate with existing domain validation (neumes, structural order, lyric anchors, accidentals, safe effective pitch). Compare resolveEffectivePitches for ALL inserted notes against captured degree AND alteration and ALL existing destination notes against pre-paste degree AND alteration, by stable ID. Do not compare only B pitch class or source sign provenance: register-specific degree matters. No requirement to preserve derived sourceAccidentalId where pitches agree; written signs themselves remain authored entities. Reject if any copied or existing pitch differs, sign placement becomes invalid, a sign is lost/merged/canonicalized or existing written sign would need relocation. In particular, insertion between an existing above-note anchor and its owner can invalidate the first-matching-B constraint even if all effective pitches agree; reject rather than silently repairing existing authored notation. An internal copied anchor remains explicit and must validate; do not silently default it because of destination context. Only the approved external-source-anchor fallback is permitted. Existing structural anchors may change as needed by reanchorScoreOrder, preserving event order; no existing written accidental, note, lyric or clef value may change. Do not use reconcileAccidentals to silently repair/drop signs as part of paste; validate the exact candidate. All four divisions and destination word starts reset accidentals; clefs/wrap do not. No new interpretation rules.
- Fail atomically: original document/history/redo/selection/focus/clipboard preserved, no autosave, no partial paste. Announce useful reason distinguishing empty clipboard, invalid target, unsafe pitch, invalid written placement, copied effective pitch conflict and existing destination pitch conflict (include affected note/pitch or ordinal where useful; no technical dump). E.g. "Cannot paste: a copied B-flat would become B-natural here." or "Cannot paste: the copied flat would change existing music after the insertion point." Avoid automatic compensating signs even if obvious. A failed copy retains prior clipboard.
- Success: one applyDocumentEdit, one autosave, clear stale note-form error/hover, remain Select, one fresh whole-neume selection or forward range from first to last pasted neume, focus final neume's first semantic note through existing focus/reveal path. Announce pasted count and if any external copied sign placement was restored (copy notice may explain snapshot normalization too). Existing note selection/focus separation maintained. Repeat Paste inserts after new range; fresh IDs each time, clipboard unchanged. Undo removes entire insertion, reconcile selection by existing stable-ID policy (clears missing endpoints, no resurrection); redo restores exact document/IDs, not a new paste and no selection resurrection. Clipboard stays intact across both. Do not add selection or clipboard to history.

## Interaction and safety

- Add compact Copy/Paste buttons in existing editor action controls, preferably near Insert/Undo/Redo, with accessible labels, shortcut hints and visible status/tooltip or existing live announcement; avoid new large toolbar or sticky height regressions. Copy disabled when no eligible musical selection or blocked mode. Paste disabled for empty clipboard, invalid target or blocked mode; no expensive candidate building solely to disable button on every render. Show clipboard count or otherwise clear indication it contains music. Buttons and shortcuts share commands/guards.
- Ctrl+C / Cmd+C and Ctrl+V / Cmd+V (no Alt, Shift, IME/composition, defaultPrevented; no accidental key-repeat paste storm; intentional separate presses work) only in the existing notation shortcut scope or explicitly scoped clipboard controls. Keep native clipboard text operations everywhere else, including input, textarea, contenteditable, title, lyric fields and actual browser text selection. Never read/write navigator.clipboard, clipboard events, or system text clipboard; do not consume invalid non-musical text copying. If an eligible in-app command is intercepted, prevent browser default once and dispatch same action as button. No global document-wide commandeering of native copy/paste, focus-only retargeting, or shortcuts in modal controls. Announce meaningful unavailable action when intentionally invoked in notation; do not eat normal native clipboard in text contexts.
- Only ordinary Select, no active lyric entry/draft/recovery/move, pending history, clef transaction, accidental anchor placement, or armed placement tool. Block both at interaction and reducer level; no implicit draft commit/cancel, placement cancellation, changing focus or clearing selection. Preserve text paste into active lyric input (including IME). Respect existing keyboard focus and escape behavior. Clipboard content not cleared by entering modes. No partial cut or deletion. The existing single-note/neume edit guards, global Lyrics and I guards remain intact.
